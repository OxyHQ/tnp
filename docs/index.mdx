# TNP (The Network Protocol)

TNP is an alternative internet namespace controlled by Oxy. Users register domains on native TLDs that exist only inside TNP (`.ox` today). Public-root and special-use TLDs are never claimable by TNP.

<Badge variant="success">Service</Badge> <Badge>DNS</Badge> <Badge>Overlay</Badge>

## What it is

TNP is a network layer over the public internet: its own namespace, resolution for that namespace, and an overlay that carries traffic to services published inside it. It is **not** DNS-only — the client ships a local resolver, a SOCKS5 proxy, an overlay transport and a service-node mode.

Public DNS keeps working. A public name resolves identically with TNP installed and without it — see the [namespace policy](https://github.com/OxyHQ/tnp/blob/main/docs/architecture/naming.md).

Domains are tied to your Oxy account. Register at [tnp.network](https://tnp.network), manage your DNS records from the web dashboard, and propose new TLDs to the community.

Alongside resolution, TNP ships an **encrypted overlay** built around the same domains: register a service node, run `tnp serve` on a port, and clients connect through relays without your IP being exposed to them. Each connection is its own circuit over a WebSocket to the relay, with a Noise NK handshake (X25519, ChaCha20-Poly1305) against a key the client verifies back to the domain owner's domain key.

<Callout type="warning">
**Current limits, stated plainly.** The overlay relay is not deployed yet. The relay cannot read traffic, but it sees your IP, the name you reach, and timing and volume. A client pins each name's domain key the first time it connects, so the API cannot substitute a service node's key for a name the client has used before — on first contact it still can. Onion routing, exit nodes and VPN mode are **not implemented**; `tnp connect --privacy private` is rejected as unavailable. TNP does not provide anonymity. See the [Phase 0 audit](https://github.com/OxyHQ/tnp/blob/main/docs/architecture/audit-2026-08-06.md) and the [privacy model](https://github.com/OxyHQ/tnp/blob/main/docs/architecture/privacy-model.md).
</Callout>

A local proxy is **not** a VPN, and TNP does not describe it as one.

## Architecture

TNP is a Bun-based monorepo of four runtimes plus one client SDK:

```
apps/
  web/            @tnp/web          Vite 8 + React 19 + Tailwind 4 + react-i18next
  api/            @tnp/api          Bun + Express 5 + drizzle-orm/PostgreSQL + @oxy.so/core
  dns-server/     @tnp/dns-server   Public DNS resolver (UDP + TCP, dns-packet)
  relay/          @tnp/relay        WebSocket relay server for the encrypted overlay
packages/
  client/         @tnp/client       Cross-platform CLI: local DNS proxy, SOCKS5 proxy,
                                    tunnel manager, service node, embedded relay.
                                    Compiles to a standalone single-file binary with Bun.
```

The pieces are intentionally decoupled — the public DNS server (`apps/dns-server`) just embeds the same `DnsProxy` class the client CLI uses, talking to the API over HTTPS for TLD list + per-domain resolution.

```
  ┌───────────────┐         ┌────────────┐         ┌──────────────┐
  │  Browser /    │   DNS   │  TNP local │   HTTPS │              │
  │  CLI tool     │ ──────▶ │  proxy or  │ ──────▶ │   tnp-api    │
  │               │         │  public DNS│         │ (PostgreSQL) │
  └───────────────┘         └────────────┘         └──────────────┘
                                  │
                                  │ overlay enabled?  (tnp connect)
                                  ▼
                            ┌──────────┐  WSS   ┌────────────────┐
                            │ SOCKS5   │ ─────▶ │   tnp-relay    │
                            │ proxy    │        │ (Oxy or comm.) │
                            └──────────┘        └────────────────┘

                                                        ▼

```

## Install

The fastest path on Linux or macOS:

```sh
curl -fsSL https://get.tnp.network | sh
```

Windows (PowerShell):

```powershell
irm https://get.tnp.network/ps | iex
```

The installer detects the platform and architecture, downloads the matching `tnp` binary from the GitHub release, and verifies it against the release's signed `SHA256SUMS` before installing it — see [security.md §7](https://github.com/OxyHQ/tnp/blob/main/docs/architecture/security.md) for what is checked where. `tnp install` runs the local resolver as a service and configures split DNS for TNP-native labels where the operating system supports it. Public DNS continues through the configured upstreams. Without the client, forward only `.ox` to the public TNP resolver (plain DNS on UDP/TCP port 53, unencrypted, no DNS-over-TLS) in your router or OS resolver; the [install page](https://tnp.network/install) has the steps. Never make it a device's or router's whole resolver: every lookup would go to TNP in plaintext.

## Quick start

### 1. Register a domain

```sh
# Browser
open https://tnp.network/register
```

Sign in with Oxy, pick a name and a native TLD (`.ox` is the current default), then submit. The registry refuses any TLD already delegated by the public DNS root or reserved for special use.

### 2. Add DNS records

From the web dashboard at `https://tnp.network/d/your.ox`:

```
A     @     203.0.113.10     3600
AAAA  @     2001:db8::1      3600
CNAME www   your.ox          3600
TXT   _verify  oxy-domain-verify=abc123   300
MX    @     mail.example.com  3600
```

Records are rows in their own `dns_records` table, keyed by `(domain_id, name, type)` — the shape the resolver queries on every lookup. Supported types: `A`, `AAAA`, `CNAME`, `TXT`, `MX`, `NS`. TTLs default to `3600` seconds.

### 3. Resolve

```sh
# Using the installed client
tnp test your.ox

# Or just open it in a browser if the client/system DNS is configured
open http://your.ox
```

### 4. (Optional) Serve a real app over the overlay

```sh
# Register a service node for your domain
TNP_TOKEN=<oxy-token> tnp serve --domain your.ox --target localhost:8080

# Anyone running `tnp connect` resolves your.ox to 127.0.0.1, the SOCKS5
# proxy picks up the connection and forwards encrypted payloads through a relay.
# Read the prototype security limits below before exposing a service.
```

## Core concepts

### Names

A TNP name is `<label>.<tld>` where `<label>` is `[a-z0-9](-[a-z0-9])*`, 1–63 chars, and `<tld>` is one of the active TNP TLDs. Subdomains are supported on resolve (`www.your.ox`) and stored per-record by name (`@` = apex).

### TLDs

Active TNP-native TLDs such as `.ox` resolve only inside TNP. Public-root and special-use labels are rejected at registration and independently filtered by both the API and resolver. For an unregistered native name, the API may return the configured parking A record; there is no hardcoded parking address.

New TLDs come from the community: `POST /tlds/propose` creates a proposal, `POST /tlds/proposals/:id/vote` upvotes / downvotes, and an Oxy admin promotes the winners to `status: 'active'`.

### Resolution flow

`GET /dns/resolve?name=foo.ox&type=A` is the single source of truth. The flow on the API side:

1. Split `name` into `subdomain`, `domainName`, `tld`.
2. Refuse public-root and special-use TLDs, then look up the native TLD. If it is not native, return no registry answers; the client already classifies it as public DNS and forwards upstream directly.
3. Look up the domain. If not registered:
   - Return the configured parking A record when parking is enabled; otherwise return no answers.
4. Filter the domain's stored records by `type` and matching subdomain (`@` or full FQDN).
5. If the domain has an online service node with a domain key and a current certificate, attach `overlay: { relay, available, domainKey, rotations, chain, kaCert }`. The client verifies all of it against its pin for the name before it opens a circuit ([security model](https://github.com/OxyHQ/tnp/blob/main/docs/architecture/security.md)).

### Caching

The public DNS server and local client share a bounded in-memory LRU cache. Positive answers follow their record TTLs within safe bounds, and NXDOMAIN answers use bounded negative caching. Public names bypass the TNP API and keep their original DNS wire format through classic DNS or RFC 8484 upstreams.

### Authentication

The API uses **Oxy authentication** (device-first, zero-cookie). Every protected endpoint requires `Authorization: Bearer <oxy-token>`; the API verifies tokens against `https://api.oxy.so` via `@oxy.so/core`'s `oxy.auth()` middleware. Users are created lazily — the first authenticated request creates the local PostgreSQL user row keyed by `oxyUserId`.

## Tech stack

| Layer | Stack |
|-------|-------|
| Web | Vite 8, React 19, TypeScript, Tailwind CSS 4, React Router 7, react-i18next (5 locales: en, zh, es, hi, fr) |
| API | Bun, Express 5, drizzle-orm over postgres.js, PostgreSQL, `@oxy.so/core` for Oxy auth |
| DNS | Bun runtime, `dns-packet` for the wire format, raw UDP + TCP sockets, DoH upstreams |
| Relay | Bun's native WebSocket server, binary frame protocol, in-memory connection registry |
| Client | Bun (compiled to single-file binary per platform: linux-x64/arm64, darwin-x64/arm64, windows-x64), `@tnp/crypto` (tweetnacl Ed25519/X25519, `@noble` ChaCha20-Poly1305 and SHA-256) for the Noise NK overlay session |
| Auth | Device-first Oxy sign-in (`@oxy.so/services`), tokens verified by `@oxy.so/core` |
