# Client SDK

`@tnp/client` is the cross-platform CLI for TNP. It bundles:

- A local **DNS proxy** (the same `DnsProxy` class the public resolver uses).
- A **SOCKS5 proxy** that intercepts TCP connections to TNP domains.
- A **WebSocket tunnel manager** that multiplexes encrypted circuits over relays.
- A **service-node** runtime (`tnp serve`) that exposes a local port to the TNP overlay.
- An embedded **relay node** (`tnp relay`) so anyone can join the relay network.
- An **interactive terminal UI** for status, settings, and operator features.

It compiles to a single-file binary via `bun build --compile` and ships per-platform releases (`linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`, `windows-x64`).

## Install

The installer downloads the binary for your platform from the fixed GitHub release URL, verifies it, installs it, and optionally installs the local service:

```sh
# Linux / macOS
curl -fsSL https://get.tnp.network | sh

# Windows (PowerShell)
irm https://get.tnp.network/ps | iex
```

Every release carries `SHA256SUMS` and `SHA256SUMS.sig`, an Ed25519 signature by the TNP release key. The shell installer checks the signature with OpenSSL 3 when it is available and the binary's SHA-256 always, before running or moving anything; when it cannot check the signature (macOS ships LibreSSL, PowerShell has no Ed25519) it says so. Set `TNP_REQUIRE_SIGNATURE=1` to refuse instead. `tnp update` always checks both, with the key built into the binary, and refuses any version that is not newer than the running one. To verify a download by hand, see [security.md §7](https://github.com/OxyHQ/tnp/blob/main/docs/architecture/security.md).

`GET https://api.tnp.network/client/latest` returns the current version (`{ "version": "x.y.z", ... }`). Clients read only the version; the download URL is always `https://github.com/OxyHQ/tnp/releases/download/v<version>/<asset>`.

## CLI commands

```
tnp                        Interactive terminal menu (arrow keys, status, settings)
tnp run                    Foreground DNS resolver (no overlay)
tnp connect [flags]        Full overlay client: DNS proxy + SOCKS5 proxy
tnp serve   [flags]        Run a service node for a domain you own
tnp relay   [flags]        Run a community relay node
tnp install                Install as a system service + configure system DNS
tnp uninstall              Remove the system service + restore DNS
tnp update                 Update to a newer signed release (verified, never a downgrade)
tnp status                 Is the resolver service running?
tnp test <domain>          Resolve a domain through the local proxy and print results
tnp version                Print version
tnp help                   Show usage
```

### `tnp connect` flags

| Flag | Description |
|------|-------------|
| `--privacy access` | Single-relay access mode. `private` is rejected until multi-hop onion routing exists. |
| `--autoconnect` | Persist the choice and start TNP on system boot. |
| `--no-autoconnect` | Disable autoconnect. |
| `--killswitch` | Block all DNS via iptables if the local proxy crashes (Linux only). |
| `--no-killswitch` | Disable kill switch. |

### `tnp serve` flags

| Flag | Description |
|------|-------------|
| `--domain <name.tld>` | The TNP domain you own. Required. |
| `--target <host:port>` | Local target to forward circuits to. Default `localhost:80`. |
| `--relay <wss://…>` | Specific relay endpoint. Defaults to picking from the API. |
| `TNP_TOKEN=<oxy-token>` (env) or `--token-stdin` | Bearer token for `/nodes/register` and `/nodes/heartbeat`. `--token <oxy-token>` still works but is deprecated: it is visible to every local user in the process list and lands in shell history. |

## Configuration file

`tnp` reads `<configDir>/config.json`:

| Platform | Config dir | Data dir |
|----------|-----------|----------|
| Linux | `/etc/tnp` | `/var/lib/tnp` |
| macOS | `/usr/local/etc/tnp` | `~/Library/Application Support/tnp` |
| Windows | `%PROGRAMDATA%\tnp` | `%LOCALAPPDATA%\tnp` |

The `TnpConfig` shape (see `packages/client/src/config.ts`):

```ts
interface TnpConfig {
  listenAddr: string;           // default "127.0.0.1"
  listenPort: number;           // default 5354
  apiBaseUrl: string;           // default "https://api.tnp.network"
  upstreamDns: string;          // default DoH: "https://1.1.1.1/dns-query,https://8.8.8.8/dns-query"
  cacheMaxEntries: number;      // default 10000; answers use record TTLs
  privacyLevel: "access";      // private is explicitly unavailable
  socksPort: number;            // default 1080
  relayPreference: "oxy" | "community" | "any";
  identityKeyPath: string;      // <dataDir>/identity.key
  relayPort: number;            // default 8080 (for `tnp relay`)
  relayEndpoint: string;        // public ws:// or wss:// URL; no guessed default
  relayLocation: string;
  relayMaxConnections: number;  // default 100
  relayBandwidth: number;       // advertised Mbit/s; 0 means unstated
  relayAuthToken: string;
  autoConnect: boolean;
  killSwitch: boolean;
  publicDnsIp: string;          // fallback DNS when local proxy is unavailable
}
```

Defaults are merged with the on-disk file every load, so adding new fields to the schema doesn't break existing installations.

## Modules

Each piece is exposed as an importable TypeScript module so other tools in the monorepo (notably `apps/dns-server`) can compose them.

### `DnsProxy` — `packages/client/src/proxy.ts`

The DNS engine. Same class that powers the public resolver. See [DNS Server](./dns-server) for the full request flow. Public methods:

```ts
class DnsProxy {
  constructor(config: TnpConfig);

  /** Bind UDP + TCP sockets on `listenAddr:listenPort`. */
  start(): Promise<void>;

  /** Close sockets, stop the recurring TLD sync. */
  stop(): void;

  /** Pull the TLD list from /dns/tlds once. */
  syncTlds(): Promise<void>;

  /** Start a recurring sync (default 5 minutes). */
  startTldSync(intervalMs?: number): void;

  /** Enable overlay routing: returns 127.0.0.1 for domains with service nodes. */
  enableOverlay(): void;
  disableOverlay(): void;

  /** Read overlay info cached during the last resolve. */
  getOverlayInfo(domain: string): DnsResolveOverlay | undefined; // unverified hint

  /** Shared API client; safe to reuse from a sibling module. */
  getApiClient(): TnpApiClient;
}
```

### `TnpApiClient` — `packages/client/src/api.ts`

Typed wrapper around the JSON API. Returns plain typed shapes, no extra layer.

```ts
class TnpApiClient {
  constructor(baseUrl: string);

  resolve(name: string, type: string): Promise<DnsAnswer[]>;
  resolveWithOverlay(name: string, type: string): Promise<ResolveResponse>;
  fetchTlds(): Promise<Array<{ name: string; custom: boolean }>>;

  // Overlay primitives (auth required for register/heartbeat)
  getServiceNode(domain: string): Promise<ServiceNodeInfo | null>;
  getRelays(operator?: "oxy" | "community"): Promise<RelayInfo[]>;
  registerServiceNode(domainId: string, chain: Grant[], kaCert: KeyAgreementCertificate, token: string): Promise<void>;
  getDomainKey(name: string): Promise<DomainKeyRecord | null>;
  registerDomainKey(request: RegisterDomainKeyRequest, token: string): Promise<DomainKeyRecord>;
  sendHeartbeat(domainId: string, connectedRelay: string, token: string): Promise<void>;
  registerRelay(request: RegisterRelayRequest, token: string): Promise<RelayRegistration>;
  sendRelayHeartbeat(endpoint: string, token: string): Promise<void>;
}
```

Every call uses an `AbortSignal.timeout(...)` so a stuck request can't deadlock the resolver.

### Overlay primitives

```
packages/client/src/
  tunnel.ts        TunnelManager: verified v1 circuits to service nodes, pooled relay links
  socks.ts         SOCKS5 server (RFC 1928); TNP-native names only, one circuit per connection
  proxy.ts         DnsProxy with `enableOverlay()` to return 127.0.0.1 for service-backed domains
  service-node.ts  `tnp serve` runtime (ServiceNode + credential preparation)
  relay-node.ts    `tnp relay`: directory registration around @tnp/relay-core
  crypto.ts        The relay's directory identity key only
  overlay/
    verify.ts      overlay block → pin check → chain → certificate → VerifiedKeyAgreementKey
    pins.ts        per-name domain-key pins (trust on first use), rollback marks
    identity.ts    domain keys, node keys, grants, rotating key-agreement certificates
    secure-circuit.ts  one end of a circuit: session, stream messages, flow control
    pipe.ts        socket ↔ circuit with backpressure both ways
    store.ts       per-user key directory (0700 / 0600)
```

The wire protocol is `@tnp/protocol` (v1: frames, Noise NK session, overlay
codecs), the key material is `@tnp/crypto`, and the relay is `@tnp/relay-core`.
Normative specs: [`transport.md`](https://github.com/OxyHQ/tnp/blob/main/docs/architecture/transport.md)
§6.1, §9 and §11, and [`security.md`](https://github.com/OxyHQ/tnp/blob/main/docs/architecture/security.md) §1.

### Tunnel manager (`tunnel.ts`)

```ts
import { TunnelManager } from "./tunnel";
import { PinStore } from "./overlay/pins";
import { OverlayStore } from "./overlay/store";

const tunnels = new TunnelManager({
  pins: new PinStore(new OverlayStore()),
  resolveOverlay: async (name) => (await api.resolveWithOverlay(name, "A")).overlay ?? null,
});

// Verifies the overlay (pin, chain, certificate) for "example.ox", opens a
// circuit, and resolves once the service node has connected to its target.
const circuit = await tunnels.openStream("www.example.ox", 443);
```

A refused key throws `OverlayVerificationError` (`pin-mismatch`, `bad-chain`,
`malformed`, `no-overlay`) before anything is sent to a relay. The circuit is
then joined to a socket with `pipeSocket` (`overlay/pipe.ts`), which applies
backpressure both ways and resets the socket if the circuit fails.

### SOCKS5 proxy (`socks.ts`)

Standard SOCKS5 (RFC 1928, no auth), loopback by default. For each `CONNECT`:

1. A name that is not TNP-native (or an IP literal) is refused locally; the API is never asked about it.
2. A native name is opened with `TunnelManager.openStream`, using the overlay block the DNS proxy cached as a hint, or resolving it.
3. The reply is sent once the service node has accepted, and bytes are piped both ways.

Browsers can be pointed at `127.0.0.1:1080` (SOCKS5) for TNP names.

### Domain keys and pins

```sh
tnp domain key init example.ox        # create + register the domain key (owner device)
tnp domain key show example.ox
tnp domain key rotate example.ox      # the old key signs the change
tnp domain grant example.ox --node-key <base64> --out grant.json   # authorize a node elsewhere
tnp pins                              # list pinned domain keys
tnp pins forget example.ox            # next contact trusts the registry again
```

## Building from source

```sh
cd packages/client

# Native binary for the current platform
bun run build

# All five release binaries
bun run build:all
```

The build outputs to `packages/client/dist/`. Output binaries are fully self-contained (Bun runtime included); they have no runtime dependencies.

## Running the dev resolver

If you just want to develop against the resolver without installing it:

```sh
cd /home/nate/Oxy/tnp
bun run dev:api   # API at http://localhost:4170

# In another terminal
bun packages/client/src/cli.ts run
# Resolver listens on 127.0.0.1:5354 by default. Override with TNP_LISTEN_*.

# Test
dig @127.0.0.1 -p 5354 yourname.ox A
```

The dev resolver hot-reloads via `bun --watch` if you start it with `bun run dev` from `packages/client`.
