# VPN (WireGuard)

TNP's standard-tier VPN is a **WireGuard** tunnel from your router, phone or computer to an exit run by TNP. Your device runs the official WireGuard client; TNP gives it a configuration and keeps the exit in sync. The keys are made on your device, and TNP only ever receives the public key.

> **Status:** implemented, not yet switched on. Until TNP deploys its first exit, the dashboard page says "Not available yet" and nothing can be added. While exits' capacity is fixed, the VPN is open to a limited group of accounts; for any other account the page says it is not available for that account. Design: [`architecture/vpn.md` §10](./architecture/vpn.md); exits: [`architecture/exit-nodes.md` §9](./architecture/exit-nodes.md).

## What it protects, and what it does not

Read this before you rely on it.

**It protects**

- **From your local network and your internet provider.** Public Wi-Fi, other people on your router and your ISP see one encrypted WireGuard connection to a TNP exit. They do not see which sites you visit, your DNS lookups, or what you send.
- **Your IP address from the sites you visit.** They see the exit's address instead.

**It does not protect**

- **From TNP.** Oxy operates the exit, so it can technically see which addresses and ports you connect to, and the content of anything the site itself does not encrypt. HTTPS hides the content, not which site you reach. Your DNS lookups go to TNP's resolver on that same exit, so the same operator sees the names you look up; it keeps no record of them. The exit keeps only totals, never per-connection records ([exit-nodes.md §9.3](./architecture/exit-nodes.md)) — but that is a promise about how we run it, and you are trusting us on it.
- **Your identity.** This is not anonymity. One company runs the exit and knows which account each device belongs to, and someone able to watch both your connection and the exit can match them up by timing.
- **What you tell a site.** Signing in to an account identifies you, VPN or not.
- **From the hosting provider** (AWS), which can observe the exit's traffic like any network operator.

**If your safety depends on not being identified** — for example, if you are an activist or a journalist facing a government — use [Tor Browser](https://www.torproject.org/), not this VPN. TNP's private, multi-hop tier does not exist yet.

**What TNP stores** for each device: the name you gave it, its public key, its tunnel address and when it was added. Never the private key, and never when it connects, from which IP address or how much it sends.

**IPv6** is not carried yet. On phones and computers, every configuration routes IPv6 into the tunnel so it cannot leak around it, and the exit refuses it with an immediate error, so apps that also speak IPv4 use that. On a router, the setup below adds the router-side rules this needs.

## Pick the nearest exit

TNP runs exits in more than one region, each shown with its place and region code — for example *Oregon (us-west-2)* or *N. Virginia (us-east-1)*. **Choose the one nearest you**: every packet makes the round trip to the exit, and your DNS is answered by TNP's resolver on that exit, so websites hand you servers near it. The page and `tnp vpn add` suggest the exit nearest your time zone; you can pick another.

A device is accepted at every exit, but each configuration names one exit (its address, key and resolver). To be able to switch, download or scan the configuration for each exit you want while the page shows the new device — the private key is only shown then.

## Add a device

1. Sign in at [tnp.network](https://tnp.network) and open **Dashboard → VPN** (`/dashboard/vpn`).
2. Type a name (for example *Home router*) and choose **Add device**. Your browser generates a WireGuard key pair and sends only the public key.
3. Choose the exit (above). The configuration appears **once**: as a downloadable `.conf` file, as a QR code and as text. It contains the private key, which TNP never had and cannot show again. If you lose it, revoke the device and add a new one.

**Prefer the download or the QR code to copying.** Copying puts the private key in your clipboard, where clipboard history or sync can keep it; if you do copy, the page overwrites the clipboard after 60 seconds where the browser allows it.

An account can have up to 10 devices. To stop a device — a lost phone, an old router — choose **revoke**. Exits stop accepting its key at their next sync, normally within a minute. An exit that cannot reach TNP stops accepting **every** device after 10 minutes, so a revocation never waits on an outage for longer than that. A revoked device's tunnel address is not given to anyone else for 24 hours.

From a terminal, the CLI does the same with the key generated on that machine:

```bash
TNP_TOKEN=… tnp vpn exits             # every exit, its region and resolver; the nearest is marked
TNP_TOKEN=… tnp vpn add laptop        # writes ./tnp-laptop.conf, mode 0600, for the nearest exit
TNP_TOKEN=… tnp vpn add laptop-us --exit use1-1   # or name the exit
tnp vpn list
tnp vpn revoke <id>
```

**Fair use.** Each exit has a fixed monthly transfer allowance. When an exit has used it up, it slows to a few megabits per second for everyone on it until the first of the next month (UTC) — browsing still works, large downloads crawl. Another exit may be faster then.

## OpenWrt router (recommended for a home)

WireGuard is built into OpenWrt. Set it up once on the router and every device on your network uses the VPN without installing anything.

The router setup differs from a phone's in three ways, all on by default:

- **It dials the exit by IP address.** The router sends its own DNS through the tunnel, so at boot it could not look up the exit's name to bring the tunnel up. The dashboard's router configuration and commands use the exit's IP.
- **IPv6 cannot leak.** OpenWrt routes IPv6 from your provider by source address (`wan6` source routing), which would beat the tunnel and send your devices' IPv6 straight to your provider. The setup turns source routing off and makes the router refuse IPv6 from the LAN with an immediate error. TNP does not carry IPv6 yet.
- **Kill switch.** The LAN's forwarding to your provider is removed, so if the tunnel is down your devices have no internet instead of silently using your provider. The router itself keeps using `wan`: it needs it to reach the exit. You can opt out on the dashboard (not recommended) or allow a fallback later.

**Packages** (once): *System → Software*, or over SSH:

```sh
opkg update && opkg install luci-proto-wireguard   # OpenWrt 25 and later: apk add luci-proto-wireguard
```

Then reboot the router.

### With LuCI

1. *Network → Interfaces → Add new interface*: name `wg0`, protocol **WireGuard VPN**.
2. *General Settings*: **Load configuration…** and paste the **router configuration** from the dashboard's OpenWrt tab (OpenWrt 23.05 and later) — the one that dials the exit by IP. On older versions, paste the private key and add the address shown on the dashboard (`10.77.x.y/32`).
3. *Peers*: check that the TNP exit peer has **Route Allowed IPs** ticked and **Persistent Keep Alive** set to `25`.
4. *Advanced Settings*: **Use custom DNS servers** with the DNS address from the configuration. Then edit the `wan` interface and untick **Use DNS servers advertised by peer**, so lookups do not go to your provider.
5. *Firewall Settings*: create a new zone `tnp`. In *Network → Firewall*, set zone `tnp` to input *reject*, forward *reject*, with **Masquerading** and **MSS clamping** on, and allow zone `lan` to forward to `tnp`.
6. **IPv6**: edit the `wan6` interface and, under *Advanced Settings*, untick **IPv6 source routing**. In *Network → Firewall → Traffic Rules*, add a rule for **IPv6** from zone `lan` to zones `wan` and `tnp`, action **reject**.
7. **Kill switch**: in *Network → Firewall*, edit zone `lan` and untick `wan` under *Allow forward to destination zones*.
8. **Save & Apply**. *Status → WireGuard* should show a recent handshake within a minute.

### With `uci` over SSH

The dashboard's **OpenWrt router** tab shows these commands filled in with your device's key and addresses. They contain the private key: paste them into the router's shell and do not save them anywhere else. The shape is:

```sh
uci -q delete network.wg0
uci set network.wg0=interface
uci set network.wg0.proto='wireguard'
uci set network.wg0.private_key='<this device's private key>'
uci add_list network.wg0.addresses='10.77.x.y/32'
uci add_list network.wg0.addresses='fd85:d596:af02::a4d:…/128'
uci add_list network.wg0.dns='<resolver>'
uci -q delete network.wg0_tnp
uci set network.wg0_tnp=wireguard_wg0
uci set network.wg0_tnp.description='TNP exit <id>'
uci set network.wg0_tnp.public_key='<exit public key>'
uci set network.wg0_tnp.endpoint_host='<exit IP address>'
uci set network.wg0_tnp.endpoint_port='51820'
uci add_list network.wg0_tnp.allowed_ips='0.0.0.0/0'
uci add_list network.wg0_tnp.allowed_ips='::/0'
uci set network.wg0_tnp.route_allowed_ips='1'
uci set network.wg0_tnp.persistent_keepalive='25'
uci set network.wan.peerdns='0'
uci -q get network.wan6 >/dev/null && uci set network.wan6.peerdns='0'
uci -q get network.wan6 >/dev/null && uci set network.wan6.sourcefilter='0'
uci -q delete firewall.tnp
uci set firewall.tnp=zone
uci set firewall.tnp.name='tnp'
uci set firewall.tnp.input='REJECT'
uci set firewall.tnp.output='ACCEPT'
uci set firewall.tnp.forward='REJECT'
uci set firewall.tnp.masq='1'
uci set firewall.tnp.mtu_fix='1'
uci add_list firewall.tnp.network='wg0'
uci -q delete firewall.tnp_lan
uci set firewall.tnp_lan=forwarding
uci set firewall.tnp_lan.src='lan'
uci set firewall.tnp_lan.dest='tnp'
# IPv6 from the LAN is refused towards wan and tnp (two rules, family ipv6, target REJECT)
uci -q delete firewall.tnp_no_v6_wan
uci set firewall.tnp_no_v6_wan=rule
# … family='ipv6' src='lan' dest='wan' proto='all' target='REJECT', and the same for dest='tnp'
# Kill switch (left out if you opt out on the dashboard): remove the lan → wan forwarding
for s in $(uci -X show firewall | sed -n 's/^firewall\.\([^.=]*\)=forwarding$/\1/p'); do
  [ "$(uci -q get firewall.$s.src)" = lan ] && [ "$(uci -q get firewall.$s.dest)" = wan ] && uci delete firewall.$s
done
uci commit network
uci commit firewall
service network restart
service firewall restart
```

### Allowing a fallback, or removing TNP

To let LAN devices use your provider again when the tunnel is down:

```sh
uci -q delete firewall.tnp_fallback
uci set firewall.tnp_fallback=forwarding
uci set firewall.tnp_fallback.src='lan'
uci set firewall.tnp_fallback.dest='wan'
uci commit firewall
service firewall restart
```

The dashboard also shows the commands that remove TNP from the router entirely: they delete the tunnel and the `tnp` firewall rules and restore your provider's DNS, IPv6 source routing and forwarding.

**IPv6 on the LAN.** With the rules above, devices that try IPv6 get an immediate refusal from the router, and nothing leaves outside the tunnel. To stop them trying at all, also turn off router advertisements on the LAN (*Network → Interfaces → lan → DHCP Server → IPv6 Settings*).

**MTU.** OpenWrt's WireGuard default (1420) suits most connections. On PPPoE (DSL, some fibre), set the `wg0` MTU to 1412 if some sites hang while loading.

## Android and iOS

1. Install the official **WireGuard** app (published by *WireGuard Development Team*) from Google Play, F-Droid or the App Store.
2. Tap **+**, choose **Scan from QR code** and scan the code on the dashboard. Name the tunnel, for example `tnp`.
3. Switch the tunnel on.

- **Android kill switch:** *Settings → Network → VPN →* the gear next to WireGuard → **Always-on VPN** and **Block connections without VPN**.
- **iOS:** in the tunnel's settings, turn on **On-Demand** activation so it reconnects by itself. iOS has no hard kill switch for third-party VPNs.

## Windows and macOS

1. Install WireGuard from [wireguard.com/install](https://www.wireguard.com/install/) (on macOS, from the Mac App Store).
2. Download the configuration from the dashboard, then **Import tunnel(s) from file** and select it.
3. **Activate**.

On Windows, a full tunnel like this one blocks all traffic outside the tunnel while it is active, so nothing leaks if the connection drops.

## Linux

```bash
sudo install -m 600 tnp-laptop.conf /etc/wireguard/tnp-laptop.conf
sudo wg-quick up tnp-laptop
sudo systemctl enable --now wg-quick@tnp-laptop   # start at every boot
```

`wg-quick` sets DNS through `resolvconf` or `systemd-resolved`; if neither is installed, your DNS does not change and lookups bypass the tunnel's resolver. `wg-quick` has no kill switch by default.

## Troubleshooting

| Symptom | Check |
|---|---|
| No handshake | UDP 51820 outbound may be blocked on your network. The device's clock must be roughly right. Was the device revoked? |
| Router never connects after a reboot | The router's peer must dial the exit by **IP address** (the dashboard's router configuration does). With a hostname and `peerdns` off, it cannot resolve the exit before the tunnel is up. |
| Handshake, but no sites load | DNS: is the configured resolver set (Linux: resolvconf/systemd-resolved)? On OpenWrt, is `peerdns` off on `wan` and the LAN forwarding to `tnp`? The resolver is `10.77.0.1`, inside the tunnel. |
| Everything is slow | The exit may be far away — pick the nearest one — or it may have used its monthly allowance and be throttled until the 1st (UTC). |
| Some sites hang | Lower the MTU (1380 is safe everywhere). |
| Mail will not send on port 25 | Exits refuse outbound SMTP on port 25 (spam). Use your provider's submission port, 587 or 465, which are open. |
| Your own LAN (192.168.x.x, 10.x) is unreachable while the tunnel is on a phone or computer | The full tunnel sends it to the exit, which refuses private, link-local and other non-public ranges by design ([exit-nodes.md §3](./architecture/exit-nodes.md)). Use the Android app's *Exclude private IPs* option, or edit `AllowedIPs` to leave your LAN out. Not an issue when the VPN runs on the router. |
